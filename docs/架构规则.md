# 架构硬规则与操作手册

本文件是第三轮重构后的**唯一架构规则入口**。阈值只在 `tools/audit/arch_rules.json` 维护，文档与 CI 都读取它，不得在别处手写数字。

## 1. 硬规则

| 规则 | 阈值 | 检查方式 |
|---|---:|---|
| 类型总行数 | ≤ 400 | `arch_metrics --enforce` |
| 单文件行数 | ≤ 450 | 同上 |
| partial 类型 | 0 | 同上 |
| 方法行数 | ≤ 80 | 同上 |
| 方法判断点 | ≤ 12 | 同上 |
| 方法参数 | ≤ 6 | `arch_metrics --enforce`（`methods`） |
| record 主构造参数 | 新增 ≤ 6；历史超大 DTO 记入 `record_param_baseline`，只降不升 | 同上（`records`） |
| `I*Host` 接口 | 0 | 同上 |
| `SessionManager` | ≤ 350 行 / 0 public | 同上 |
| `Program` | ≤ 200 行 / `Main` ≤ 80 | 同上 |
| 测试方法 | ≥ 230 | 同上 |
| 组件测试映射 | 每个组件 ≥ 2 个测试；`direct` 组件必须出现组件名 | 同上 + 契约测试 |
| SPLIT 命名空间 | 0 | 同上（`namespaces.split`） |
| 无日志 catch | ≤ 66 | 同上 |
| public 类型 | 不超过 `arch_rules.json` 基线 | 同上 + 契约测试 |
| 架构 allowlist | 空 | 契约测试 `ArchitectureAllowlistIsEmpty` |

## 2. 允许的拆分方式

- **大类型**：核心类型 + 操作组（`*Ops`）或上下文字段，持有 `_host`/`_core` 引用；禁止再引入 `I*Host`。
- **长方法**：提取私有方法或纯逻辑协作类型；控制流、错误码、消息文本必须保持原样。
- **多参数**：用 `record`/`readonly record struct` 请求对象，只放数据字段，不放行为；新构造对象必须 ≤ 6 参数（必要时再拆一层）。历史超大 DTO 已记入 `record_param_baseline`，只允许减少。
- **命名**：一个文件一个主类型；`*Ops` 表示操作子集，`*Context` 表示只读回调集合。

## 3. 禁止项

- 新增 `partial`、新增 public 类型、放宽 `arch_rules.json` 阈值；
- 用 `[SuppressMessage]`、`#pragma` 或反射绕过度量；
- 把逻辑塞进请求 record（record 只承载数据）；
- 删除/改写既有测试来“通过”新规则；
- 引入新的第三方依赖或新的程序集。

## 5. 故障排查

| 现象 | 处理 |
|---|---|
| `--enforce` 报方法超限 | 先跑 `--inventory` 拿清单，按“提取方法/请求对象”处理，不要抬阈值 |
| 报 `partial 类型` | 改成独立协作类型，不要用 partial 合并 |
| 报 `I*Host` | 改成传上下文 record（回调集合），而不是接口 |
| 报组件测试不足 | 在 `arch_rules.json` 的 `components` 里补映射，并真的写 ≥2 个测试 |
| 报 public 类型超基线 | 新增辅助类型必须 `internal`；需要公开时先在评审中说明 |
| `doc_metrics --check` 失败 | 跑 `doc_metrics --write` 重新生成 `architecture.md` 的度量块 |
| 文档链接失败 | 修 `docs/` 内相对链接，不要删检查 |
