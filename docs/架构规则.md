# 架构参考与拆分建议

> 本文件是架构评审与重构的**参考手册**，不是 CI 闸门。
> 行数、方法长度、判断点、参数个数、测试数量、组件映射、record 参数基线等指标只用于判断“是否值得拆分”，不再阻塞提交。
> 真实边界仍由契约测试守护：命名空间单归属、IVT 白名单、程序集引用方向、Automation 不暴露 public 类型。

## 1. 参考指标

| 指标 | 参考值 | 说明 |
|---|---:|---|
| 类型总行数 | ≤ 420 | 超过时优先考虑拆分操作组 |
| 单文件行数 | ≤ 450 | 超过时检查是否混入多个职责 |
| partial 类型 | 0 | 新代码优先用独立协作类型，而不是 partial |
| 方法行数 | ≤ 80 | 超过时考虑提取阶段方法 |
| 方法判断点 | ≤ 12 | 超过时考虑策略对象或提前返回 |
| 方法参数 | ≤ 6 | 超过时用请求 record |
| `I*Host` 接口 | 0 | 用 `*Context` 只读回调集合替代 |
| `SessionManager` | ≤ 350 行 / 0 public | 只做组合根 |
| `Program` | ≤ 200 行 / `Main` ≤ 80 | 只做入口分流 |
| 测试方法 | 不强制数量 | 以行为覆盖为准，不设“不得减少”棘轮 |

这些数值来自 `tools/audit/arch_rules.json`，可用 `python tools/audit/arch_metrics.py --inventory` 查看当前值；不再由 CI 的 `--enforce` 执行。

## 2. 推荐的拆分方式

- **大类型**：核心类型 + 操作组（`*Ops`）或上下文字段，持有 `_host`/`_core` 引用；不建议再引入 `I*Host`。
- **长方法**：提取私有方法或纯逻辑协作类型；控制流、错误码、消息文本保持原样。
- **多参数**：用 `record`/`readonly record struct` 请求对象，只放数据字段，不放行为。
- **命名**：一个文件一个主类型；`*Ops` 表示操作子集，`*Context` 表示只读回调集合。

## 3. 仍然禁止的事项

- 用 `[SuppressMessage]`、`#pragma` 或反射绕过真实边界测试；
- 把业务逻辑塞进请求 record（record 只承载数据）；
- 删除或改写既有行为测试来“通过”评审；
- 未经评审引入新的第三方依赖或新的程序集。

## 5. 评审时的判断

| 现象 | 建议 |
|---|---|
| 文件/类型明显变大 | 先判断是否混入多个职责；必要时拆操作组，不为了指标而拆 |
| 方法超过参考行数 | 提取阶段方法或纯逻辑协作类型，保持错误码与文案不变 |
| 参数过多 | 引入请求 record；record 只放数据 |
| 出现 partial | 优先改成独立协作类型；确有需要时在评审中说明 |
| 出现 `I*Host` | 改成 `*Context` 回调集合 |
| 新增 public 类型 | 默认 `internal`；需要公开时先评审 |
| 需要看指标 | 跑 `arch_metrics.py --inventory`，不要把数字写回文档 |
