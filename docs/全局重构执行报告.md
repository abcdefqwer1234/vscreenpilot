### 2.6 P5：工具层重写（核心）

- `ToolDescriptor`：名称/标题/描述/输入输出 schema/超时/策略/处理器。
- `ToolPolicy`：`Mutates`、`ScreenLeaseMode`（None/Always/EnsureOption/SnapshotOptions/WaitCondition/IfLiveApps）、`SessionRead`、`SessionWrite`、`BypassWriteLock`、`WriteTimeoutMs`。
- `ToolRegistry`：22 个描述符的唯一登记处。
- `ToolExecutor`：租约、写调度、超时/取消、epoch 校验、trace 与进度收口；只读取 `ToolDescriptor.Policy`。
- **删除** `MutatingTools`、`RequiresScreenLease(string, args)`、`KeepsForeground(args)`、`sessionRead/sessionWrite` 名称硬编码与 `release_environment` 的三处特判。
- `McpServer` 更名为 `McpTransport`，并拆为：
  - `Mcp/McpTransport.cs`（698 行）：协议宿主、工具列表/调用入口、资源读取、trace；
  - `Tools/ToolCatalog.cs`（475 行）：22 个工具的 schema 与策略声明；
  - `Tools/ToolHandlers.cs`（643 行）：参数解析与领域调用；
  - `Tools/ToolDescriptor.cs`、`Tools/ToolExecutor.cs`。
- 新增 `ToolPolicyTests`（7 个用例）：22 个工具唯一、schema/handler 完整、destructive ⇒ mutates、SessionWrite ⇒ bypass + 短超时、release 策略、只读观察者不取租约、注册表语义。

### 2.7 P7：UIA 单线程宿主

- 新增 `Automation/Ui/UiaHost.cs`：专用 MTA 工作线程 + `BlockingCollection` 队列；所有 `UiaService` 服务级调用（建树、查找、焦点、文本、值）在 worker 上串行执行。
- `Retire()` 只退休当前代际并让新调用创建新线程；旧线程把队列剩余工作做完后自行释放 COM，不在调用线程 Dispose。
- `SessionManager.ResetUia()` 改为 `UiaHost.Retire()`；`_uia` / `_retiredUia` 状态从会话移除。
- 取消令牌在调用方固化为 `CancellationProbe()`，避免 `AsyncLocal` 不跨手工线程流动导致 snapshot 超时不生效。
- 句柄级操作（`UiaElementHandle.Focus/Invoke/GetText`）仍走 `UiaService._sync`（MTA 对象可跨线程），后续可并入同一队列。

验证（真实 GUI）：
- `bench_protocol` 22 工具 + SEC-10「大树 + ref 可用」通过（11 节点、11 ref、0 stale）；修复了工作线程 `Thread.Start` 传参导致的 `E_INTERNAL`。
- 自建压测：100 轮 `snapshot` + `find_element`（200 次工具调用）零失败，句柄 316→321，RSS 132.69→132.77MB。
- 说明：`bench_concurrency` 的 CONC-01/02 超时在**未包含 UiaHost 的旧构建**上同样复现，属当前环境/负载问题，不是本次回归。

### 2.8 P8：无类型空捕获

- 59 处 `catch { ... }` 改为 `catch (Exception exception)`，保留原注释并显式 `_ = exception;`，控制流不变。
- 剩余 25 处已收窄类型的空捕获补 `_ = exception;` 与原因注释（`COMException`、`DllNotFoundException`、`OperationCanceledException` 等）。
- 仓库内空捕获统计归零。
- 全量重建 0 warning。
