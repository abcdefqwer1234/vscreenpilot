### 审计说明

`bench_protocol.py` 全绿，说明协议、工具 schema、错误码、取消、超时、租约、release 清理在真实 MCP 会话下没有回退。

两个审计环境问题已定位并修复：

1. **审计靶标必须 self-contained**：`dotnet build -o` 产出 framework-dependent 版本，服务端子进程没有 `DOTNET_ROOT` 时靶标会弹“You must install or update .NET”。nightly 已改为 `dotnet publish -r win-x64 --self-contained true`。
2. **`--out` 必须用绝对路径**：GUI-01/GUI-04 的 oracle 路径是相对路径时，Notepad/UiTarget 的工作目录不同，会打开空文档或写文件失败，进而级联出 GUI-05..09 的 `E_NO_TARGET`。改用绝对 `--out` 后恢复 13/14。

最终审计结果（同一二进制、绝对输出目录、独立 profile）：

## 5. 偏差、风险与回滚

偏差：

- R2-3 采用 **partial 文件**而非独立类；满足“单文件 ≤600”，但组件的宿主依赖仍集中（`IInputHost` 26 个成员），独立测试能力改善有限。独立类抽取留到 R3。
- R2-4 已完成 16/16，最大方法 148；`Launch` 通过 `LaunchState` 拆为 10 个阶段。
- R2-7 已完成；`ResetUia` 保留为显式清理入口。
- 覆盖率未设阈值；仅保留内置 `--collect:"Code Coverage"` 的用法说明。

风险：

- `LogSink` 使用全局 `Trace` listener，测试与多 profile 进程会各写各的 `trace-<profile>.log`；文件句柄保持到进程退出。
- 37 处 catch 统一提升为 `Exception` 变量并记录 Debug，可能增加日志量；错误码与对外输出未变。
- partial 拆分是纯搬运，但仍建议在具备 VDD 的环境补跑 GUI/protocol/stability/UIA。

回滚：

- 整体回滚：`git checkout r2-baseline`（tag 指向 R2-0 提交前的起点）。
- 分阶段回滚：每个阶段一个提交，可单独 revert；R2-2 的类型搬迁与命名空间修正必须整体回滚。
- 分支：`refactor/r2`，未推送远端。
