## 1. 结论

VScreenPilot 的核心价值不在“18 个工具”，而在三件事：

1. **真正的隔离**：Parsec 虚拟显示器 + 焦点/光标护栏 + tracked 窗口校验；高 star 桌面 MCP 基本都直接操作用户桌面。
2. **完整的生命周期**：互斥体、状态文件、心跳、孤儿屏接管、父进程退出、EOF 清理。
3. **克制的安全默认值**：越界拒绝、系统键黑名单、`run_script` 默认关闭、破坏性写入保护。

它的上限被四件事卡住：

- **协议层是手写的**，停在 2025-06-18，`outputSchema` 是空壳；
- **感知层只有一个 GDI 后端**，连续全屏 19–24 次后跌到 1.9s；
- **UIA 没有专用线程**，并发/超时/取消全部靠一把大锁和 `Task.Wait`；
- **工具面是 18 个细粒度动词**，一次观察要 3–4 个往返，ref 无快照作用域，失败不可复盘。

因而不建议重写（会丢掉上述核心价值），建议按“接口先行、逐层替换”的绞杀式路线，把上限抬到“可探测、可归因、可验证”。

## 3. 两份报告的可信度问题

1. **CONT-01 的“18/18 一致”是空校验**：schema 为 `{"type":"object"}`，任何对象都能过，不能作为协议成熟度加分项。
2. **GUI-04/08 的 `0x80070003` 未定位**：报告归因“未包装的 UIA 异常”，但 `ERROR_PATH_NOT_FOUND` 更像 provider/legacy 路径失败；这是唯一会连带目标进程退出的故障，应单独立项。
3. **66/100 不宜继续维护**：性能项 5/10 偏宽松，测试项 7/10 偏乐观。后续改用“能力矩阵 + SLO 表”。

## 6. 目标架构

```
Transport/Protocol   官方 MCP C# SDK（实测 2025-11-25；目标 2026-07-28，兼容 2025-06-18）
                     stdio 默认；Streamable HTTP 可选（Bearer/TLS/限流）
                     toolset: snapshot / screenshot / act / query / app / session / artifact
        │
SessionKernel        租约调度（display/uia/input/capture/clipboard/script）
                     epoch + 每调用 CTS + 健康检查 + 多 profile
        │
Workers              DisplayWorker(MTA) · UiaWorker(MTA，独占 IUIAutomation)
                     MsaaWorker · InputWorker · CaptureWorker · ScriptWorker
        │
Backends             UIA3 | UIA2/MSAA | CDP | OCR | 消息 | SendInput | 剪贴板
                     WGC | DXGI | GDI | PrintWindow
Adapters             generic | Office | Chromium/WebView2 | UWP | 单实例多标签
        │
Observability        session.jsonl · artifact · metrics · HTML report
Security             错误目录 · 限流 · 审计 · 路径 jail · 脚本隔离
```

### 六个核心机制

1. **租约调度**：只读观察不被长任务阻塞；`wait_for` 每轮单独租。
2. **快照模型**：`snapshot_id` + ref 作用域；行式紧凑格式；节点带 value/state/text。
3. **通道探测**：接管时生成 `AppProfile{channels, preferred, caveats}`，工具默认 `channel=auto`。
4. **动作验证**：每个写操作带廉价后置条件（UIA 属性/标题/像素/文件 mtime/对话框），返回 `verified`。
5. **能力分组 + 资源**：`core/vision/office/chromium/script`；大产物走 `vsp://`。
6. **可复盘**：每次调用一行 JSONL；会话结束生成 HTML 报告。

## 9. 风险

- WGC 在 Parsec IDD 上是否可用未知 → 先 spike，不可用则 GDI 池化 + 去 `CAPTUREBLT` + 周期性重建 DC。
- FlaUI 替换可能性能回退 → 包在接口后 A/B。
- CDP 需目标应用开端口 → 定位可选能力。
- MSAA 对个别 Office 版本仍可能失败 → 再退键盘 + COM oracle。
- OCR 小字号精度有限 → 只用于定位/验证。
- 多会话输入所有权物理排他 → 文档明确。
- TFM 提升到 `net10.0-windows10.0.19041.0` → 最低 Win10 2004。
