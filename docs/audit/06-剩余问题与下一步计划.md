## 2. 历史问题清单（R1–R30，run6 已关闭）

> 下列表格保留复现证据与当时的修复建议。run6 已逐项处理，验证见 [03 §15.6](03-实际测试报告-Word.md)；
> 未完成的是 §2.3 的能力缺口，而不是 R1–R30。

### 2.1 P1：会误导调用方或造成竞态

| # | 问题 | 证据 | 影响 | 建议 |
| --- | --- | --- | --- | --- |
| R1 | **`get_ui_tree` 静默让 `find_element` 的 ref 失效** | `GetUiTree` 在构建前调 `BeginSnapshot()`；`FindElement` 返回值没有 `snapshot_id`；跨代 ref 在 `RequireElementEntry` 返回 `E_STALE_SNAPSHOT` | 模型按“find → get_ui_tree → invoke”操作会突然拿到 `E_STALE_SNAPSHOT`，且不知道哪个快照才是当前 | 让 `find_element` 返回 `snapshot_id`；或只在 `snapshot` 推进代际，`get_ui_tree` 复用当前代；错误里带 `current_snapshot` |
| R2 | **`release_environment` 等不到写租约仍继续清理** | `McpServer` `TryEnterExclusive(3000)`；失败时 `writeHeld=false`，handler 仍执行 `ReleaseEnvironment` | 只读 snapshot/capture 可能正在读 UIA/屏幕，release 同时清 `_apps`、摘屏；epoch 丢弃结果但中途会报 `E_INTERNAL`/`E_DISPLAY` | 等不到写锁就返回 `E_BUSY`（带 retry），或先取消/等待所有读租约 |
| R3 | **嵌套参数没有统一 schema 校验** | `RejectUnknownArguments` 只查顶层；嵌套 `region`/`expectation`/`condition` 没有递归校验；`expectation.coverage:"x"` 走 `GetDouble` fallback 0.9；`name_match`/`prefer` 等字符串枚举也没有集中校验 | 拼错/类型错的字段会静默用默认值，测试仍“通过” | 引入完整 JSON Schema 校验（nested `additionalProperties:false`、enum、range），失败返回 `field/path/expected/actual` |

## 3. 仍需注意的边界

1. **快照代际已收紧**：`get_ui_tree`/`find_element` 复用当前代，只有 `snapshot` 或显式 `new_snapshot=true` 推进；旧代仍会返回 `E_STALE_SNAPSHOT`。
2. **release 现在是硬失败**：3s 拿不到写租约返回 `E_BUSY`，不会再“边读边清理”。
3. **资源路径语义**：`save_path` 是唯一正式产物；未指定时才写 `artifact_path`。`requested_path` 已移除。
4. **`Text()` 已复制 structuredContent**：handler 后续修改 payload 不再影响 text。
5. **测试口径**：PRT-05/06/07 仍按“SDK 行为可接受”判定；不能据此宣称完全符合 MCP 规范。
6. **GUI-12 的 oracle**：验证模板/颜色/像素管线，不验证自绘 canvas 坐标。
7. **UIA 隔离**：`invoke` 5s 超时 + `ResetUia` 退休队列能避免永久卡死，但一个卡死的 provider 仍会占用 `_sync` 一段时间。
