> 依据：[07-静态审查](07-静态审查报告-PPT轮.md)、[09-实际测试报告](09-实际测试报告-PPT.md)

> 日期：2026-11-15
> 原则：先修“会误导调用方/让结果不可信”的问题，再补能力，最后做发布。

## 0. 结论先行

本轮实测把问题分成了两类：

1. **协议与语义缺陷**（修起来便宜、收益立竿见影）：图片不是 base64、`document_ready` 说谎、release 默认强杀、多 profile 挂不上去、空快照不解释。
2. **能力缺口**（要大投入）：画布型应用没有语义、动作没有后置验证、没有 OCR/CDP。

建议顺序：**P0 两周内修完 → 动作验证与 OCR 作为下一阶段主攻 → 分发/治理最后补**。不要先做“更多工具”，当前 20 个工具的用法已经够，缺的是“看得见”和“验得了”。

## 1. P0：不修就不能用于无人值守

### P0-1 内联图片必须是合法 base64

**现象**：`capture_screen`/`snapshot` 返回的 image content 在 OpenCode 侧报
`Invalid Base64 string`；原始 stdout 的 `data` 是原始二进制（PNG 头 + U+FFFD），不是 base64。

**根因（定位到两层）**：
- `McpServer.ToResult` 把 `ToolResponse` 里的 base64 字符串解码回 `byte[]` 再塞给 `ImageContentBlock.Data`（`McpServer.cs:687-694`）。
- SDK 2.4.0 把该字段写成 **UTF-8 文本**而不是 base64（原始 JSON 已证实）。

**修复（任选其一，建议 A+B）**：
- A. 不要经 `byte[]` 中转：在 `ToResult` 里直接用原始 base64 字符串构造内容块（如果 SDK 暴露 string 重载），或在发送前自校验 `Convert.TryFromBase64String`。
- B. 加协议级单测：对 `capture_screen{region:100x100}` 的响应断言 `content[1].data` 能通过严格 base64 解码，并且解码后以 `\x89PNG` 开头。这个测试必须跑在 CI 的 smoke 里（无需 GUI，用 `--no-warmup` 时可用 1×1 的假图或直接单测 `ToResult`）。
- C. 短期 workaround（文档 + 工具行为）：`inline` 默认改 `false`，并在响应里明确 `screenshot_path`；避免模型拿到不可用的 image block。

**验收**：OpenCode 里 `capture_screen{scale:0.5}` 直接回图，不再报错；单测覆盖。

### P0-2 画布型应用要有“第二双眼睛”

**现象**：PowerPoint 的 `snapshot` 只有 15–22 个容器节点，画布文本 0/15 命中；所有操作退化为坐标+键盘，28 次截图里大部分用于“看有没有生效”。

**方案（按性价比排序）**：

1. **带标注的截图（最快，1–2 天）**
   - `snapshot{annotate:true}`：在截图上画 UIA 元素的框 + 序号，返回 `annotations[]`（序号→ref）。
   - 对画布类应用没有 ref 时，至少叠加**网格坐标**（参考 Windows-MCP 的 `width_reference_line/height_reference_line`），让模型报坐标更准。
   - 成本：`PngWriter` 已有缩放/绘制基础，加矩形和文字即可；无新依赖。

2. **OCR（1 周，WinRT TFM）**
   - 新工具 `read_screen_text{region}` → `[{text, bounds, confidence}]`；`find_text{text}` → 坐标。
   - 用 `Windows.Media.Ocr`（系统自带，中英模型随语言包）；把 Server 的 TFM 加 `net10.0-windows10.0.19041.0` 即可。
   - 用途：PPT/图表/自绘控件/游戏 UI 的文本定位；也可给 `click` 提供“按文本点击”。
   - 注意：OCR 结果不能当唯一事实来源，必须带置信度与区域。

3. **CDP / IAccessible2（2–3 周，仅浏览器类）**
   - 对 CefSharp/WebView2/Electron：启动参数加 `--remote-debugging-port`，或复用已开的端口；提供 `dom_snapshot`/`dom_click`。
   - 只在检测到 Chromium 类窗口时启用；不要试图用消息注入绕过。

**验收**：PPT 场景里“找到标题占位符/表格单元格/图片”不再依赖人工估算坐标；`click` 前的定位步骤 ≤ 1 次调用。

### P0-3 空快照必须解释自己

**现象**：并发用例里 `snapshot` 返回 `nodes:1`，无错误、无 `truncated`、无原因；调用方无法区分“应用没控件”和“UIA 忙”。

**修复**：
- 当 `nodes <= 1` 且 `root.Children.Count == 0` 时，返回 `empty_reason`（`uia_busy`/`permission`/`custom_ui`/`time_budget`），并按需重试一次（200ms）。
- 若 `pruned == visited`，明确 `pruned_all:true`，提示改用 `interactive_only=false`。

## 2. P1：会误导调用方或造成隐性失败

| ID | 修复 | 具体做法 | 验收 |
| --- | --- | --- | --- |
| S1 多 profile 挂不上 | 二次设置位置 | `TryActivateDisplay` 在首次 `ChangeDisplaySettingsEx` 成功后**再调用一次**（位置在激活后才生效）；`settled` 失败时先 `ExtendDesktop` 再重试；仍失败则接受实际位置并记录 `actual_x/y` | 不带 `VSP_DISPLAY_OFFSET` 的 profile 也能挂载；两个 profile 并行各有屏 |
| S3 Office 就绪误报 | 分应用探测 | `document_ready` 改为：Word 看 `Document`；PPT 看窗口标题是否含 ` - PowerPoint` 且存在 `Pane 工作区`；Excel 看 `工作簿`；不确定时返回 `document_ready:null` + `reason` | 开始屏幕返回 false；新建后返回 true |
| S5 超时不取消 | 协作式取消 | handler 接受 `CancellationToken`；在 `EnsureEnvironment`/`Uia.BuildTree`/输入循环里检查；超时后把会话标记 `busy_until`，拒绝新的写操作直到旧 handler 结束 | 超时后 1s 内不再有新的鼠标/键盘事件 |
| S6 release 默认丢数据 | 默认改 `abort` | `on_dirty` 默认 `abort`；`force` 需要 `allow_data_loss:true`；返回值里区分 `closed/forced/kept` | 未保存的 PPT 不会被默认杀 |
| S7 剪贴板只还原文本 | 全格式快照 | 用 `OleGetClipboard`/`OleSetClipboard` 保存所有格式；或在检测到非文本格式时**拒绝走剪贴板通道**并回退 SendInput | 输入 300 字后，剪贴板里的图片仍在 |
| S15 动作无验证 | 统一 `observed` | `click`/`press_keys`/`gesture` 返回 `observed:{changed:bool, region, hash_before/after}`：动作前后各抓一次 64×64 缩略图对比；`expect` 参数可选 | 30% 的“无效点击”能在同一调用里被发现 |
| N3 坐标点击脆弱 | 语义优先 + 失败自愈 | `click` 失败时自动尝试 `input` 一次（可选 `auto_fallback:true`）；`click_ref` 失败时重新 snapshot 并重定位 | flow 12 步 0 次 `E_INPUT_UNSUPPORTED` |
| N4 空快照 | 见 P0-3 | — | — |
| N5 死进程残留 | 清理 `_apps` | `GetEnvironment`/`snapshot` 前移除 `alive:false` 且超过 3s 的条目；或返回 `alive:false` 但标记 `stale:true` | 恢复用例返回 1 条 |
| N6 dialogs 与 root 不一致 | 统一口径 | 当 snapshot root 不是主窗口时，把 root 也列进 `dialogs[]`（带 `is_root:true`） | 字体/保存对话框可被识别 |
| 邮箱泄露 | 隐私过滤 | `snapshot` 的文本里对 `\S+@\S+` 做脱敏（保留域名首字母）；或对 Backstage/账户区域默认裁剪 | 快照不再出现完整邮箱 |

## 3. P2：成熟度与工程化

### 3.1 协议与工具面

- **`readOnlyHint` 诚实化**：`get_environment(ensure)`、`snapshot`、`capture_screen` 会挂屏/换代/写盘，改为非只读，或拆出 `ensure_display`。
- **标准资源链接**：大图用 `resource_link` 内容块（而不是 JSON 里的 `vsp://` 字符串），客户端可直接渲染。
- **HTTP 传输**：至少支持 `--transport streamable-http`（Windows-MCP 已有 SSE/HTTP），便于多客户端与远程。
- **`tasks`（2025-11-25 实验特性）**：把 `press_keys` 序列、长输入、soak 类操作做成可轮询任务，避免客户端超时。
- **工具面收敛**：20 个工具已经偏多。考虑把 `click_ref` 与 `invoke_element` 合并，`capture_screen` 与 `snapshot` 的截图参数统一；同时提供 **CLI 伴生入口**（`vscreenpilot snapshot --json`），让编码代理用 CLI+skill 省 schema token（playwright-mcp 已明确走这条路）。

### 3.2 测试工程

- 新增的 `tools/audit/ppt/*` 应进 nightly 自托管 runner；PPT 场景固定 4 页脚本化版本（`bench_ppt_flow` 已具备雏形）。
- 补 6 个协议级单测：image base64、空快照原因、`document_ready` 三态、release 默认值、死进程清理、dialogs 一致性。
- CI 加覆盖率门槛（先 40%，核心类 60%）与 `dotnet format --verify-no-changes`。
- 审计脚本增加 `--profile` 参数（现在依赖 `VSP_PROFILE` 环境变量，容易与常驻实例抢互斥体）。

### 3.3 分发与生态

- 建 GitHub 仓库/Release，签名 exe，补 `server.json`（MCP Registry），把 winget 清单里的占位 URL/SHA 换成真实值。
- npm 发布 `vscreenpilot@0.2.0`；同时提供 `dnx` 或独立原生包（`PackAsTool` 不支持 `net10.0-windows` 的限制可用 native AOT 包装器绕过）。
- 100MB 单文件偏大：考虑 framework-dependent + 引导下载，或按 RID 分发 zip。

### 3.4 文档与治理

- `技术文档.md`/`需求文件.md` 与实现冲突（18 工具、手写 JSON-RPC）→ 重写或标注历史。
- `README.md` run5 → run6/PPT 轮；`changes` 里“winget/Registry 已就绪”改为“待发布”。
- 补 `README.en.md`、`CONTRIBUTING.md`、`SECURITY.md`、`CHANGELOG.md`。
- `docs/errors.md` 为每个错误码加 `###` 锚点；删除 5 条死码或实现它们；`E_DIALOG_UNREACHABLE` 的 hint 改成真实能力。

### 3.5 安全性表述

- `run_script` 的黑名单可被 `iwr`/`curl`/`&`/字符串拼接绕过。建议：
  - 目录里明确写“黑名单只防误触，不是安全边界”；
  - 或去掉黑名单，只保留 `--allow-script` + 审计日志；
  - 真要隔离，用 VM/AppContainer，不要在这里做半套。

## 5. 路线图

### 阶段 1（1–2 周）：修 P0/P1 的“信任问题”

1. P0-1 图片 base64 + 协议单测。
2. P0-3 空快照原因；N5 死进程；N6 dialogs。
3. S1 多 profile 位置；S3 Office 三态；S6 默认 `abort`；邮箱脱敏。
4. S15 统一 `observed`（先做 click/press_keys 的 64×64 差异）。

**出口标准**：OpenCode 内 `capture_screen` 直接回图；PPT 场景调用数从 118 降到 ≤ 80；flow 0 次 `E_INPUT_UNSUPPORTED`。

### 阶段 2（2–3 周）：补“看得见”

1. `snapshot{annotate:true}` + 网格叠加。
2. OCR：`read_screen_text` / `find_text`（WinRT TFM）。
3. `click_text`（OCR 定位 + 消息/输入点击 + 后置验证）。
4. `--transport streamable-http` + `tasks`（长操作）。

**出口标准**：PPT 场景 ≤ 50 次调用、≤ 10 张截图；画布类应用能“按文本定位”。

### 阶段 3（2 周）：发布与治理

1. GitHub Release + 签名 + winget/Registry/npm。
2. PT 场景进 nightly CI；覆盖率门槛；英文 README + 治理文件。
3. 文档与实现对齐。

**出口标准**：外部用户 `npx vscreenpilot` 或 `winget install` 可用；CI 有可复现的 PPT/Word 回归。

## 6. 不建议做的事

- **不要**继续堆工具数量。当前瓶颈是“看不见/验不了”，不是“功能少”。
- **不要**把 `run_script` 当安全边界；它是逃生舱，不是沙箱。
- **不要**试图让 UIA 覆盖 PPT 画布；Office 不会给，投入产出比极低。
- **不要**在非默认 profile 位置问题上打补丁式重试；先把 `ChangeDisplaySettingsEx` 的两次调用做对。
- **不要**为了让报告好看而放宽 SLO；本轮的 `auto` 点击 P95 412ms 超了 300ms 目标，应记录而不是改阈值。
