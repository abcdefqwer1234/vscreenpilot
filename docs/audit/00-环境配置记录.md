## 3. 环境问题与处理

### 3.1 Parsec VDD 0.45 在 VMware 上崩溃

- 初始只用 `winget install --id Parsec.ParsecVDD` 安装了 **0.45.0.0**。
- `--doctor` 显示驱动 Ok；但第一次 `capture_screen` 耗时约 **10 秒**，随后设备进入 **Code 43（`CM_PROB_FAILED_POST_START`）**。
- 系统事件：
  - `Microsoft-Windows-DriverFrameworks-UserMode` 10111 / 10120 / 10121；
  - `Parsec Virtual Display Adapter` 用户模式驱动 `mm.dll` 异常。
- 处理：卸载 0.45，改用官方 **0.41.0.0**（`parsec-vdd-0.41.0.0.exe /S`，自动替换旧驱动）。
- 结果：设备 `OK / CM_PROB_NONE`；截图恢复到 **30–48ms**；未再出现 Code 43。

> 结论：在这台 VMware 虚拟机上，**Parsec VDD 0.41 是可用版本，0.45 不稳定**。后续测试固定 0.41，并在报告中记录。

### 3.2 驱动启停冷却时间

- `VddProbe stress --count 20 --holdms 500 --postremove 300`：**4/20 ADD 失败**，错误 31。
- `VddProbe stress --count 10 --holdms 500 --postremove 3000`：**10/10 通过**，add ioctl 约 1.4ms，remove 约 2.2s。
- 结论：REMOVE 后需要约 3 秒冷却；后续压力/会话测试使用 `--postremove 3000`，不要用默认 300ms。

### 3.3 Notepad 首次 `type_text` 返回 `E_FOCUS`

- `launch_or_place_app` 成功，窗口已移动到虚拟屏并最大化。
- 直接 `type_text` 返回 `E_FOCUS`；`get_environment.foreground.tracked=false`。
- 先对窗口中心执行 `click { mode: "message", keep_foreground: true }`，再 `type_text` 成功，`verified=true`。
- 结论：`launch_or_place_app` 不主动抢前台；在 VMware/当前桌面环境下，`EnsureForeground` 单独切前台不一定成功。测试 GUI-01 时应先做一次消息点击/显式聚焦；这也是后续改进建议的候选点。
