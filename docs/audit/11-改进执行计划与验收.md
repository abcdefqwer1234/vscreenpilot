## 0. 先修正基线认知

07 §14 原先把本轮写成“SDK 不变、工具数不变”，与代码不符。实际对比：

| 项 | run6（`c86f6fd`） | 本轮（`2ef5334`） |
| --- | --- | --- |
| 协议 | 手写行式 JSON-RPC（988 行） | 官方 SDK 2.4.0 |
| 工具 | 18 | 20（+`snapshot`、`click_ref`） |
| 参数校验 | 无 | 递归校验器 |
| 错误 | `E_INTERNAL` 退化 | 53 条目录 + 统一信封 |
| 进度 | 无 | `notifications/progress` |

所以本轮不是“没进步”，而是“底座进步被新暴露的契约缺陷抵消”。下面的批次按“性价比”排序，不按问题编号。

## 1. 批次 1：修“工具说谎”（1–3 天）

| ID | 问题 | 改动 | 主要文件 | 验收 |
| --- | --- | --- | --- | --- |

| B1-3 | `document_ready` 恒 true | 三态：Word 看 `Document`；PowerPoint/Excel 看窗口标题是否含文档名；未知应用返回 `null` + `document_ready_reason`；`ensure_document` 仅 Word 承诺，PPT 尝试 `Ctrl+N` 后如实回报 | `SessionManager.Apps.cs` | 开始屏幕 `false`；打开 deck 后 `true`；普通 Win32 应用 `null` |
| B1-4 | release 默认强杀 | `on_dirty` 默认 `abort`；`force`/`discard` 需要显式 `allow_data_loss=true` | `McpServer.cs`、`SessionManager.cs` | UNS-01 改为“默认不杀”；显式 force 才杀 |
| B1-5 | 剪贴板丢图片/文件 | `EnumClipboardFormats` 检测非文本格式；`auto` 回退 SendInput，显式 `clipboard` 返回 `E_CLIPBOARD_UNSAFE`；`Restore(null)` 改为清空而不是写空串 | `ClipboardText.cs`、`SessionManager.Input.cs` | SUP-12 通过（图片仍在） |
| B1-6 | 空快照无解释 | `nodes<=1` 时重试一次并把 `empty_reason` 写进结果（`uia_busy`/`custom_ui`/`pruned_all`/`root_not_found`） | `SessionManager.Snapshot.cs` | 人为并发忙时能看到原因 |
| B1-7 | 死进程残留 | `GetEnvironment`/`snapshot` 前清理死亡超过 3s 的 `_apps` 条目 | `SessionManager.cs` | 恢复用例 `apps[]` 只剩存活项 |
| B1-8 | `dialogs` 与 root 不一致 | root 是弹窗时，`dialogs[]` 补 `is_root:true`，并输出 `root_hwnd` | `SessionManager.Snapshot.cs` | 保存/字体对话框可被识别 |
| B1-9 | 快照泄露邮箱 | `snapshot.text`/窗口标题做邮箱脱敏，返回 `privacy_redactions` | `SessionManager.Snapshot.cs` | 快照不再出现完整邮箱 |
| B1-10 | `readOnlyHint` 不符 | `get_environment(ensure)`/`snapshot`/`capture_screen` 改为非只读；会话读锁不再依赖该标注 | `McpServer.cs` | `tools/list` 标注与行为一致 |

## 4. 本机无法完成、需要外部条件的项

| 项 | 原因 | 需要什么 |
| --- | --- | --- |
| GitHub Release / 代码签名 | 仓库无 remote，无证书 | 远端地址 + 签名证书 |
| npm 发布 | 无 npm token，包名未注册 | npm 账号与发布权限 |
