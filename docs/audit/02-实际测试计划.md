### 1.3 对“成熟”的判定口径

本测试不把“能跑一次”当作成熟。成熟至少需要同时满足：

- **可构建**：干净机器能按文档构建，SDK/依赖版本受控；
- **可协议**：MCP 生命周期、tools、错误、取消、schema 行为符合规范；
- **可稳定**：50 会话、30min soak、故障注入无崩溃、无残留、清理 ≤5s；
- **可兼容**：目标应用（至少 Win32/WinForms/WPF/Office，重点 Word）能用；
- **可安全**：越界/外来窗口/破坏性操作/脚本执行有明确边界；
- **可维护**：有 CI、单元测试、release、包管理、文档、问题跟踪；
- **可对比**：与同类高 star 项目相比，差距有合理解释，不是“功能缺失但自称成熟”。

## 4. 测试策略

### 4.1 方法

- **黑盒为主**：通过 MCP stdio 调用工具，不依赖内部 API；记录输入/输出/耗时/错误码。
- **白盒补充**：对静态审查发现的 P0/P1 做定向实验（如 `MOUSEEVENTF_VIRTUALDESK`、ref 容量、baseline x/y）。
- **Oracle 独立**：文件内容、UiTarget 写出的 JSON、Word `.docx` 解压后的 XML、截图人工核对；不只用 MCP 自己的返回判断成功。
- **对照实验**：对 P0 输入缺陷，做“原始构建 vs 补丁构建”对照；对 Word，做“MCP 操作 vs 手动/键盘操作”对照。
- **可复现**：所有脚本、命令、环境变量、随机种子、原始结果保留。

### 4.2 测试层次

```text
L0 构建/环境
L1 协议/契约/安全（无 GUI）
L2 GUI 基线（UiTarget/Notepad/Calculator）
L3 真实项目（Word 文档）
L4 性能/稳定性/故障注入
L5 对比与报告
```

### 4.3 观测与记录

每次工具调用记录：

- 工具名、参数（敏感内容截断）、开始/结束时间、耗时；
- `isError`、错误码、`hint/stage`；
- 返回字节数、图片字节数、structuredContent 是否存在；
- 是否移动光标、前台窗口是否变化、目标进程/窗口；
- 人工干预（点击 UAC、重启、手动改配置等）。

环境记录：

- 进程 RSS、句柄数、CPU、线程数；
- 显示器数量/拓扑、虚拟屏坐标/DPI；
- 残留进程、临时目录、state.json、日志。

### 4.4 OpenCode 任务卡（AI 直接调用）

AI 直接调用 MCP 时，每个任务按任务卡执行，避免发散和不可比：

| 字段 | 内容 |
| --- | --- |
| 任务 ID | 例如 GUI-01、W-05、EXP-01 |
| 目标 | 一句话说明要完成的用户可见结果 |
| 允许工具 | 例如 `launch_or_place_app`/`capture_screen`/`find_element`/`type_text`/`press_keys` |
| Oracle | 文件内容/靶标 JSON/docx XML/截图 |
| 最大调用次数 | 例如 20 次；超过即记录“效率失败”，不再无限重试 |
| 停止条件 | Oracle 满足 / 出现不可恢复错误 / 达到最大调用次数 |
| 记录 | transcript、工具调用序列、错误码、重试、截图、人工干预 |

示例任务卡：

```text
ID: GUI-01
目标: 用 MCP 在 Notepad 中输入“Hello 虚拟屏 123 / 第二行 ABC”并保存
允许工具: launch_or_place_app, type_text, press_keys, get_element_text, capture_screen
Oracle: 文件内容包含两行文本
最大调用: 15
停止: Oracle 满足；或 E_FOCUS/E_NO_TARGET 连续 3 次
记录: 每次调用的工具/参数/耗时/错误码、是否 verified、是否人工干预
```

```text
ID: W-05
目标: 在 Word 文档中插入 2×2 表格并填写 4 个单元格
允许工具: press_keys, type_text, find_element, get_element_text, capture_screen
Oracle: docx 的 word/document.xml 含 w:tbl 与 4 个 w:t 文本
最大调用: 12
停止: XML oracle 满足；或确认 UIA/键盘两条路径都不可用
记录: 通道（UIA/keyboard/message/input）、失败码、重试次数
```

**AI 直接调用不等于“只允许 AI”**：Python 可以旁路采样，但不能代替 AI 选择工具、处理错误或完成 GUI 操作；否则“体验评价”无效。

### 阶段 2：输入 bug 与 GUI 基线（约 90 分钟）

#### 2.1 P0 输入坐标对照实验（必做）

目的：确认 `mode=input` 是否把虚拟屏坐标映射到主屏。

方法：

1. 在 `tools/audit/targets/` 下新增一个最小 WinForms 点击日志靶标（`ClickProbe`，不改生产代码），记录 `WM_LBUTTONDOWN` 的屏幕坐标和窗口句柄；
2. `launch_or_place_app` 把 ClickProbe 放到虚拟屏；
3. 调用 `click { x: <虚拟屏内坐标>, y: ..., mode: "input" }`；
4. 检查日志：
   - **原始构建**：预期日志无记录或记录到主屏坐标 → 确认 P0；
   - **补丁构建**（临时副本加 `MOUSEEVENTF_VIRTUALDESK`）：预期记录到虚拟屏坐标；
5. 同样测 `gesture drag/scroll/move`。

注意：`InputInjector.Click` 在 `finally` 里恢复光标，不能靠调用后的 `get_environment.cursor` 判断；必须用目标窗口日志或实时采样。

> 执行方式：**Python 负责重复测量**（原始 vs 补丁、坐标误差、P95）；**OpenCode AI 负责真实调用体验**（模型是否会选 `mode=input`、错误提示是否可操作、重试次数）。两者都做，结果分开标注。

- 50 会话循环：spawn → initialize → get_environment → capture_screen → release → EOF；统计成功率和耗时。
- 30 分钟 soak：截图/UIA/输入循环；每 100ms 采样 RSS/句柄/光标/前台；记录异常。
- 12 项故障注入：
  1. 应用中途退出；
  2. 外部摘屏（VddProbe removeall）；
  3. 坐标越界；
  4. 外来窗口；
  5. 无效 PNG；
  6. 超长路径；
  7. 取消请求；
  8. EOF 中断；
  9. 重复实例；
  10. 管理员窗口/UIPI（只验证 `E_UIPI` 错误路径，不要求成功操作）；
  11. 慢启动应用；
  12. UIA 空结果/卡死。

> 执行方式：本组全部由 **Python** 执行，AI 只读报告；故障 #10 的目标是验证错误码和提示，而不是成功操作管理员窗口。

#### 4.3 并发

- 8 线程 × 20 次调用：`get_environment`、`get_log`、`capture_screen`、`find_element`；
- 记录 E_BUSY、超时、串行化程度、是否崩溃；
- 16 线程 × 10 次作为加压；
- 并发中调用 `release_environment`，验证闸门重置和清理。

> 执行方式：本组由 **Python** 执行；目的是验证“单闸门串行化”在并发下是否稳定、E_BUSY 是否可解释、release 能否恢复，而不是追求吞吐量。

#### 4.4 清理与残留

每次会话后检查：

- `Get-Process VScreenPilot,notepad,WINWORD,EXCEL,CCW`；
- `Get-PnpDevice -Class Display` 的 Parsec 设备；
- `monitors` 数量；
- `%LOCALAPPDATA%\VScreenPilot` 状态/日志；
- 临时 profile/脚本目录；
- 光标位置、前台窗口是否恢复。

> 执行方式：**Python 自动检查 + 人工抽查**；检查结果写入 `summary.json` 的 `residual` 字段。

### 6.7 Python 与 OpenCode 的边界

- **Python 可以**：启动/停止服务端、发送 MCP JSON-RPC、采样 RSS/句柄/光标/前台、执行文件/注册表/进程 oracle、生成报告。
- **Python 不可以**代替“AI 在 OpenCode 中的体验”：GUI-01..15 与 W-01..W-10 的 AI 版必须由本对话直接调用 MCP 工具；Python 只能旁路采样与 docx oracle。
- **同一任务双轨**：Python 版用于 P50/P95/失败率；OpenCode 版用于工具选择、错误提示、恢复、token/上下文和人工干预次数。报告中分别标注 `source=python` / `source=opencode-ai`。

| 归因 | 判定依据 | 示例 |
| --- | --- | --- |

| 模型误用 | 参数/工具选择错误，但工具本身按契约工作 | 用 `click` 点 CefSharp 而不是 `mode=input` |

| 每轮 GUI/稳定性前 | `VddProbe removeall`、结束残留进程、清空 `%LOCALAPPDATA%\VScreenPilot` | 保证干净基线 |

| 测试结束 | 按需恢复 `pre-install` 或保留 `post-Word` | 交付可复现环境 |

注意：`cleanupRuntime`/测试脚本会删除 `%LOCALAPPDATA%\VScreenPilot`，只允许在测试 VM/独立账户中执行；不要在有用户数据的机器上直接跑。
